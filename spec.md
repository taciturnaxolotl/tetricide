# tetricide spec

Tetris for the Terasic DE1 (Cyclone II EP2C20F484C7), written in VHDL,
played with a PS/2 keyboard, drawn on a 640x480 VGA monitor. Built for the
EGCP 1010 Lab 8 creative design.

## Target

| thing | value |
| --- | --- |
| board | DE1, Cyclone II EP2C20 (18,752 LEs, 52 M4K blocks) |
| toolchain | Quartus II 13.0 SP1 (last release with Cyclone II) |
| language | VHDL-93, `ieee.numeric_std` only |
| pixel clock | 25 MHz, `CLOCK_50` divided by 2 |
| video | 640x480 @ 60 Hz, 4 bits per channel through the DE1 resistor DAC |
| input | PS/2 keyboard, `PS2_CLK` / `PS2_DAT` |

Everything is simulated on a Mac with [nvc](https://www.nickg.me.uk/nvc/)
before it goes near Quartus. Quartus only does fit, timing and the bitstream.

## Block diagram

```
 PS2_CLK ─┐  ┌──────────┐ held keys  ┌────────────┐ board, piece,  ┌──────────┐ R,G,B[3..0]
 PS2_DAT ─┴─▶│ ps2_keys │──────────▶│ game_logic │──ghost, next──▶│ renderer │────────────┐
             └──────────┘ key_event  └────────────┘ lines, level   └──────────┘            │
                                        ▲      │                        ▲                   ▼
 CLOCK_50 ─▶ ÷2 ─▶ clk25 ─────────┬─────┘      └─▶ lines/level BCD      │ pixel row, col  ┌─────┐
                                  │               ─▶ HEX3..0           │                 │ reg │─▶ VGA
                                  └─▶ ┌────────────┐ vert_sync ────────┘                 └─────┘
                                      │ vga_timing │───────────────────────────────────────▲ HS,VS
                                      └────────────┘
```

`tetris_core` wraps `ps2_keys`, `game_logic` and `renderer` behind plain
`std_logic_vector` ports so Quartus can make a schematic symbol for it.
`tetricide` is the full top level with DE1 pin names.

## Blocks

### ps2_keys

Runs on `clk25`, not on the keyboard clock, so a glitch or a dropped bit can
never leave it out of step.

- `PS2_CLK` and `PS2_DAT` go through two sync flip-flops and an 8-sample
  glitch filter. Bits are taken on each falling edge of the filtered clock.
- An 11-bit frame is accepted only if the start bit is 0, the stop bit is 1
  and the parity is odd. A bad frame is thrown away.
- If no clock edge comes for about 1.3 ms the bit counter resets, so the
  decoder resynchronizes on the next frame.
- `E0` (extended) and `F0` (break) prefixes set flags for the next byte.
- Output is the held state of each action, plus a one-clock `key_event` pulse
  on every make or break.

| action | keys |
| --- | --- |
| left | ← (E0 6B), A (1C) |
| right | → (E0 74), D (23) |
| soft drop | ↓ (E0 72), S (1B) |
| rotate clockwise | ↑ (E0 75), W (1D), X (22) |
| rotate counterclockwise | Z (1A) |
| hard drop / restart | space (29) |

### game_logic

All state lives here, clocked at 25 MHz. Once per frame, on the rising edge of
`vert_sync`, a small state machine runs. Each step proposes a position for the
piece, a single shared collision checker answers on the next clock, and the
step either commits the move or rejects it. All of this finishes inside the
vertical blanking interval (33 lines, about 26,000 clocks), so the screen
never shows a half-updated frame.

**State**

| signal | size | meaning |
| --- | --- | --- |
| `board` | 20 rows x 10 cells x 3 bits = 600 FFs | landed cells, 0 = empty, 1..7 = piece color |
| `cur`, `rot` | 3 + 2 bits | falling piece shape and rotation |
| `px`, `py` | 4 + 5 bits | position of the piece's 4x4 box |
| `ghost` | 5 bits | row the piece would land on |
| `nxt` | 3 bits | preview piece |
| `lines` | 16 bits BCD | lines cleared, 0000 to 9999 |
| `level` | 0..29 plus 2 BCD digits | gravity speed |

The board is registers rather than M4K RAM because collision needs four rows
at once and line clearing needs all 20 at once; a RAM reads one address per
clock.

The falling piece is never written into the board while it falls. It is kept
as shape, rotation and position, and the renderer draws it on top. It is
written into the board only when it locks.

**Coordinates.** `px` is a *padded* column: board column = `px + c - 3`.
Padded columns 0-2 and 13-15 are walls and rows 20-23 are floor, so the
collision check treats walls and floor as filled cells and needs no special
cases. `px` is 0..12, `py` is 0..20.

**Pieces.** 28 masks, 16 bits each (7 shapes x 4 rotations), generated by
`tools/gen_pieces.py` into `src/pieces.vhd`. Shapes and spawn orientations
follow the SRS guideline; bit `15 - (4r + c)` is row `r`, column `c`.

| index | shape | color |
| --- | --- | --- |
| 0 | I | cyan |
| 1 | O | yellow |
| 2 | T | purple |
| 3 | S | green |
| 4 | Z | red |
| 5 | J | blue |
| 6 | L | orange |

**Collision.** For each of the 16 mask bits that is set, look up
`occupied(px + c, py + r)`. This takes four 24:1 row muxes and some 16:1 bit
muxes, which is far smaller than 16 separate 200:1 cell lookups.

**One frame**

1. Latch every key press seen since the last frame, so a short tap is never
   lost between two frames.
2. **Rotate**, if asked: try kick offsets 0, -1, +1 (I piece also -2, +2). The
   first spot that fits wins.
3. **Move** left or right on a fresh press. When a direction is held, it
   repeats after 16 frames and then every 6 frames (NES delayed auto shift).
4. **Fall:**
   - hard drop: step down one row per clock until it hits, then lock
   - otherwise, on a gravity tick (or every 2nd frame while soft drop is held):
     step down one row, and lock if it can't
5. **Ghost**: step down from `py` until it hits, and record the last row that
   fit.

**Lock → clear → spawn**

- **Lock:** write the piece's four cells into the board in its color.
- **Clear:** find the lowest full row and shift every row above it down one,
  then repeat. That is one clock per cleared row, so it takes at most 4
  clocks. Each cleared row adds 1 to `lines`, and every 10 lines adds 1 to
  `level`.
- **Spawn:** `cur ← nxt`, `nxt ← random`, `px = 6`, `py = 0`, rotation 0. If
  the new piece collides, the game is over.
- **Game over:** the board turns gray. Space restarts.

**Gravity**, in frames per row by level (NES):
48 43 38 33 28 23 18 13 8 6 5 5 5 4 4 4 3 3 3 2 2 2 2 2 2 2 2 2 2 1.
The starting level comes from `SW[3..0]` and is clamped to 9.

**Randomness.** A 16-bit LFSR steps every clock and holds still for one clock
on every `key_event`. A key press lands on an unpredictable 40 ns clock, so
every press shifts the sequence by a different amount. When a new piece is
needed, the LFSR's low 3 bits pick it. If that gives 7, or the same piece as
the current preview, the next 3 bits get one reroll (the NES rule).

**Test hook.** `force_piece` ≠ `111` makes the next spawn that piece. The top
level ties it to `111`; the testbench uses it to set up exact scenarios.

### renderer

Purely combinational: it turns a pixel's (row, column) into a 12-bit color.

Layout on 640x480:

| region | x | y |
| --- | --- | --- |
| `TETRICIDE` logo, 8 px blocks | 180..459 | 28..67 |
| board frame | 232..407 | 88..423 |
| board cells, 16 px each | 240..399 | 96..415 |
| stats panel (`LINES`, `LEVEL`) | 56..199 | 112..231 |
| next-piece panel | 440..551 | 112..223 |
| controls panel | 56..199 | 288..391 |

All the art is generated by `tools/gen_art.py` into `src/art.vhd`, so it is
redrawn in Python, not by editing VHDL:

- **Font:** 5x7 pixel glyphs for ASCII 32..95, drawn at 2x (10x14 px on a
  12 px pitch). Text is matched with comparators per character, so there is no
  divider.
- **Logo:** `TETRICIDE` spelled in a 35x5 grid of 8 px beveled blocks, each
  letter in a tetromino color.
- **Background:** a 16-step navy-to-plum vertical gradient, ordered-dithered
  with a 4x4 Bayer matrix so the steps blend.
- **Panels:** 4 px beveled frames (light top-left, dark bottom-right) around
  a dark fill.
- **Board:** cell origin on 16 px boundaries, so the cell index is the upper
  bits of the pixel coordinate minus a constant. Cells have a 2 px bevel, and
  the empty well has a faint dot at each cell corner.
- **Ghost:** on `SW[9]`. The piece's color at 1/4 brightness, with a 1 px
  edge at 1/2 brightness drawn only on the outside of the shape.
- **Game over:** stack turns gray, frame stays, a black banner reads
  `GAME OVER` / `PRESS SPACE`.

Palette, as `RGB` 4 bits each:

| color | base | highlight | shadow |
| --- | --- | --- | --- |
| cyan | 0EE | 8FF | 088 |
| yellow | EE0 | FF8 | 880 |
| purple | A0E | D8F | 608 |
| green | 0D0 | 8F8 | 070 |
| red | E00 | F88 | 800 |
| blue | 22F | 88F | 008 |
| orange | F80 | FC8 | 940 |
| gray (game over) | 888 | CCC | 444 |

If you have to use Dr. Kohl's `VGA_SYNC` with 1-bit color, wire the MSB of
each channel. Every piece is still a distinct color except orange, which
becomes yellow.

### vga_timing

Standard 640x480 timing at 25 MHz: an 800-clock line (640 visible, 16 front
porch, 96 sync, 48 back porch) and a 525-line frame (480 visible, 10 front
porch, 2 sync, 33 back porch). Both syncs are negative. `tetricide` registers
the renderer's color together with the syncs, so they stay aligned.

### tetricide (DE1 top)

| port | use |
| --- | --- |
| `CLOCK_50` | ÷2 → 25 MHz |
| `KEY[0]` | reset (active low) |
| `SW[3..0]` | starting level |
| `SW[9]` | ghost piece on/off |
| `PS2_CLK`, `PS2_DAT` | keyboard |
| `VGA_R/G/B[3..0]`, `VGA_HS`, `VGA_VS` | monitor |
| `HEX3..HEX0` | lines cleared |
| `LEDG[7..0]` | level, in BCD |
| `LEDR[9]` | game over |

## Workflow

```
nix develop          # nvc, imagemagick, python
make sim             # analyze, run the testbench, write sim/out/*.png
make pieces          # regenerate src/pieces.vhd
make art             # regenerate src/art.vhd
```

The testbench sends real PS/2 frames, ticks `vert_sync` quickly, checks board
cells by sampling the renderer at cell centers, and dumps full 640x480
screenshots.

In Quartus: add `src/*.vhd` to the lab8 project, set `tetricide` as top level
(or make a symbol for `tetris_core` and wire it in the `.bdf`), assign pins
from the DE1 pin table, compile, and program.

## Risks

- **Renderer timing.** The pixel path (board mux, mask lookup, palette) must
  settle in 40 ns. If Quartus misses timing, register `pixel_row` and
  `pixel_col` one clock earlier, i.e. compute pixel n+1.
- **Clock from a divider.** `clk25` comes from a flip-flop, not a PLL. That
  is fine on Cyclone II, but Quartus should be told it is a clock
  (`create_generated_clock`). Using a PLL from the MegaWizard is the clean
  fix.
